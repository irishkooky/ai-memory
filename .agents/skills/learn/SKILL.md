# 学習ループの実行手順

目的: **同じ直しを二度させない**。この1件を直すのではなく、次に同じ場面で最初から正解に着くためのルールを残す。

## 1. セッションを最初から遡る

次の3種類を全部拾う(文面の直しだけに絞らない):

- **成果物への直し**: AIの出力を本人が書き換えた/差し戻した箇所。「AIドラフト」と「正」を対にする
- **前提知識の不足**: 本人が補足した事実(「うちは法人契約しか受けない」「会長は数字より現場の声で動く」)
- **提案の方向性のズレ**: 「それはやらない」「そこじゃない」と言われた提案。何が前提から外れていたか

## 2. 一般ルールに言語化する

「最初からどう答えていれば差し戻しなしで正解に着けたか」を1〜2行で書く。判定は「次の似た場面で、このルールを読めば同じ結果が出るか」。

- 悪い例: 「この返信の締めを『〜いただければと思います』に直す」
- 良い例: 「依頼の締めは命令形にしない。『〜ください』→『〜いただければと思います』(初回接触の相手には命令形が強い)」

## 3. 置き場所を決める(AGENTS.md の表)

| 学びの種類 | 書き先 |
|---|---|
| 所有者・会社の事実、好み、前提 | `profile.md` |
| 決定事項 | `decisions.md` |
| 文面・成果物への直し | `feedback.md` |
| 特定の相手にだけ効くこと | `people/<相手名>.md` |
| 特定の案件にだけ効くこと | `projects/<案件名>.md` |
| 作業の手順・型 | `.claude/skills/<名前>/SKILL.md`(なければ作る) |
| エージェントの振る舞い全般 | `AGENTS.md` |

## 4. 追記する

- 日付と出所を付ける: `(YYYY-MM-DD・〇〇の送信版から確定)`
- 既存ルールと矛盾するなら、古い方を書き換える。併記しない
- 既存の見出しに入るなら新しい見出しを作らない(記憶は少なく濃く)
- `current.md` を触ったら冒頭の最終更新日を更新する

## 5. 出す前の検査

- [ ] 追記したルールを読んで、そのルールだけで次回同じ結果が出るか
- [ ] 「この件」固有の固有名詞が一般ルール側に混ざっていないか(固有のものは people/ か projects/ へ)
- [ ] 機密・個人情報を書いていないか

## 6. コミット・プッシュ

```bash
git add -A && git commit -m "<ファイル名> <何を学んだか1行>" && git push
```

作業ブランチが指定されている環境では、そのブランチにプッシュしたあと `main` へのマージ・プッシュまで自分で完了させる。

## 7. 本人への報告

何を・どのファイルに・どういう一般ルールとして書いたかを1〜3行で伝える。ルールの文言そのものを見せる(本人が違うと思えばその場で直せる)。
